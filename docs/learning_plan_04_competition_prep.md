## 阶段1：让系统在DK-2500上跑起来 (5月)

### 目标
DK-2500上运行GeoCoT推理，单图<60秒

### 需要学的东西
| 技能 | 学习内容 | 预计时间 |
|------|---------|---------|
| OpenVINO基础 | 模型导出、量化、推理API | 2天 |
| ONNX格式 | PyTorch→ONNX转换 | 半天 |
| NNCF量化 | INT4/INT8量化方法 | 1天 |
| Linux基础 | DK-2500上的包管理、环境配置 | 1天 |

### 具体步骤
1. DK-2500联网后，安装OpenVINO和依赖
2. 在笔记本上测试模型导出：`python scripts/export_openvino.py`
3. 在笔记本上测试量化：`python scripts/quantize_model.py`
4. 把导出的模型拷贝到DK-2500
5. 在DK-2500上运行推理并测量速度

### 可能遇到的问题
- **OpenVINO不支持Qwen2-VL**：改用llama.cpp + GGUF格式
- **量化后精度明显下降**：用INT8代替INT4，或尝试数据感知量化
- **DK-2500内存不够**：减少max_new_tokens，降低图像分辨率

## 阶段2：评估和优化 (5月下旬)

### 目标
500张测试图上跑出可量化的结果

### 需要学的东西
| 技能 | 学习内容 | 预计时间 |
|------|---------|---------|
| 评估指标 | 分类准确率、距离误差、Haversine公式 | 半天 |
| 实验设计 | 控制变量、对比实验 | 半天 |
| 数据分析 | 用pandas整理结果、画图 | 1天 |

### 具体步骤
1. 准备500张Ground Truth图像
2. 运行GeoCoT + 零样本基线，收集结果
3. 用 `GeoClassificationMetrics.py` 计算准确率
4. 用 `GeoDistanceChecker.py` 计算距离误差
5. 生成对比表格和图表

### 关键对比实验
| 实验 | 变量 | 目的 |
|------|------|------|
| GeoCoT vs 零样本 | 有无推理链 | 证明CoT有效 |
| 3阶段 vs 2阶段 | 阶段数量 | 找最优架构 |
| INT8 vs INT4 vs FP16 | 量化精度 | 找精度-速度平衡 |
| 不同提示词 | 提示词设计 | 找最优提示 |

## 阶段3：Demo和答辩准备 (6月)

### 目标
能在DK-2500上实时演示，有说服力的答辩材料

### Demo开发
- Flask应用（`src/demo/app.py`已有框架）
- 上传图片 → 展示3阶段推理 → 地图标记位置
- 准备5-10张"效果最好"的演示图片

### 答辩材料
1. **系统架构图**：展示3阶段CoT流水线
2. **性能对比表**：GeoCoT vs 零样本 vs GPT-4o（如果数据集允许）
3. **消融实验表**：证明每个设计选择有效
4. **演示视频**：3分钟，展示从上传到出结果的全过程
5. **技术亮点总结**：离线部署、CoT推理、Intel硬件优化

### 答辩常见问题准备
| 问题 | 回答要点 |
|------|---------|
| 为什么用CoT而不是直接分类？ | 对比数据：CoT准确率 > 零样本 |
| 为什么选Qwen2-VL？ | 多语言能力对全球地理定位重要 |
| 怎么处理幻觉？ | LOCATION格式约束 + 多模式正则提取 |
| DK-2500上的优化？ | OpenVINO量化 + 图像编码缓存 + token限制 |
| 与GPT-4o方案的对比？ | 完全离线、低延迟、无API成本 |
