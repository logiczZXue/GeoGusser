================================================================================
  图寻模型架构迭代报告
  日期：2026-05-16
  项目：Intel Cup 嵌入式AI竞赛 — 离线视觉定位（徒步眼镜）
  设备：Intel DK-2500 部署目标 / RTX 4060 Laptop 开发环境
================================================================================

  核心组件：
    - GeoCoT（VLM视觉推理）：Qwen2-VL-2B，看图分析场景、地貌、文化要素
    - MoE（混合专家回归MLP）：4个场景专家 + 1个Router，从视觉特征回归坐标
    - 鳌太线级联：GeoCoT为MoE提供空间约束，缩小候选区域

================================================================================
  架构 1：GeoCoT + 单MLP回归头（Phase 1，今日之前）
================================================================================

  流程图：
    Image → GeoCoT(VLM) → 提取视觉特征(1536维) → 单个MLP回归头 → 坐标(lat,lng)

  底层逻辑：
    - GeoCoT和MLP各干各的，VLM负责"看场景"，MLP负责"算坐标"
    - 一个MLP要覆盖中国960万km²的所有场景（从漠河到海南、从上海到西藏）
    - 没有场景分治，没有空间先验

  精度：全局平均误差 ~118km

  问题：中国太大，单MLP无法同时学好所有场景的坐标映射


================================================================================
  架构 2：场景分治 MoE（Phase 2，今日之前）
================================================================================

  流程图：
                         ┌→ Expert 0 (Urban城市) ──────────┐
    Image → Feature(1536) → Router(MLP) → Expert 1 (Karst/Granite喀斯特) → WeightedSum → 坐标
                         ├→ Expert 2 (Alpine高山) ──────────┤
                         └→ Expert 3 (Other其他) ───────────┘

  底层逻辑：
    - 核心洞察：不同场景的地理空间分布不同
      城市集中在东部平原 → Expert 0 专注于东部坐标范围
      喀斯特/花岗岩在西南+华南 → Expert 1 专注于西南坐标范围
      高山雪峰在西部 → Expert 2 专注于西部高海拔坐标范围
    - Router是纯视觉驱动的：看到高楼激活Urban专家，看到雪峰激活Alpine专家
    - 每个专家在其擅长的场景内做精确回归
    - 预测 = Σ(router_weight_i × expert_i(features))

  关键设计细节：
    - RouterMLP: 1536 → 256 → 128 → 4 (带temperature=0.1的softmax)
    - 损失函数: Haversine距离 + 熵正则(防止坍缩到单一专家) + 负载均衡
    - 训练三阶段: ①独立预训练各专家 ②冻结专家训练Router ③联合微调

  精度：误差从118km → 64.9km，下降45%

  这一步的精度提升来自架构红利——让专家各司其职，而非改进VLM


================================================================================
  架构 3：鳌太线级联（Phase 3，昨日实现 + 今日三轮门控调试）
================================================================================

  命名来源：鳌太线（鳌山→太白山），秦岭徒步路线，目标野外场景

  流程图：
    Image → GeoCoT 3-Stage → StructuredParser → SpatialKB → ConstraintBox
                  │                                              │
                  │                                     ┌────────┘
                  │                                     │ (门控)
                  ▼                                     ▼
           视觉特征(1536) ────────────────────→ ConstrainedMoE → 坐标

  三级空间收窄：
    MACRO阶段    → ~1500km 半径  （中国大陆尺度）
    REGIONAL阶段 →  ~200km 半径  （省份尺度）
    LOCAL阶段    →   ~50km 半径  （景区尺度）

  底层逻辑转变（与架构2的本质区别）：

    架构2: GeoCoT ⟂ MoE（并行，互不影响）
    架构3: GeoCoT → MoE（级联，GeoCoT为MoE提供空间先验）

    核心洞察——GeoCoT和MoE的能力互补：
    ┌──────────────┬─────────────────────┬──────────────────────┐
    │              │      GeoCoT         │        MoE           │
    ├──────────────┼─────────────────────┼──────────────────────┤
    │ 擅长的        │ 粗定位：看到雪山→西部 │ 精确回归：特征→数字    │
    │              │ 看到喀斯特→西南      │                      │
    ├──────────────┼─────────────────────┼──────────────────────┤
    │ 不擅长的      │ 精确算坐标           │ 地理常识：不知道中国在哪 │
    │              │ 距离误差可能上千公里   │ 可能预测到太平洋里      │
    └──────────────┴─────────────────────┴──────────────────────┘

    所以：让GeoCoT先缩小候选区域（960万km² → 一个省的几万km²），
    然后MoE在这个小区域内做精确回归。

  新增4个模块：
    C1. StructuredParser  — GeoCoT自由文本 → 结构化地理实体（地形/植被/建筑/地名）
    C2. SpatialKB         — 地理实体 → 候选空间区域（查知识库坐标）
    C3. SpatialConstraint — 多层约束融合（MACRO∩REGIONAL∩LOCAL）
    C4. CascadePipeline   — 编排完整6阶段流程

  修改2个模块：
    C5. MoERegressor.predict_constrained() — 带空间约束的坐标预测
    C6. GeoCoTWithRegression._run_cascade_path() — 集成级联入口

  ── 今日三轮门控调试 ─────────────────────────────────────────────

  门控设计是级联架构最关键的工程决策——什么时候让约束生效？

  版本1（强制约束）：
    逻辑：约束始终生效，MoE预测偏离约束中心时拉向中心
    精度：327km（比纯MoE的64.9km更差）
    原因：GeoCoT识别不出具体地名时，KB匹配到随机条目，
          约束中心完全错误，把正确的MoE预测拉跑了

  版本2（弱门控）：
    逻辑：仅当MoE偏离约束>100km时才修正
    精度：318km（依然差）
    原因：高山场景下GeoCoT只能说"中国某地"，KB仍然随机匹配到
          1400+公里外的条目，约束中心还是错的

  版本3（四重门控——最终版）：
    逻辑：四个条件同时满足才激活约束
      ① GeoCoT识别出具体地名（不是泛泛的"中国"）
      ② 约束置信度 > 0.6（KB匹配靠谱）
      ③ MoE预测偏离约束 > 100km（MoE可能错了）
      ④ Router置信度 < 0.8（MoE自己不自信）
    精度：64.9km（= 纯MoE，7/8测试完全相同）

    V3的底层逻辑：
      "GeoCoT真看到了黄山松？→ 开门 → 约束生效，帮MoE一把"
      "GeoCoT只看到'一片树林'？→ 关门 → 纯MoE，不添乱"

    7/8测试中门是关着的——因为2B的VLM确实"看不清"细粒度地理要素


================================================================================
  架构 4：强化 GeoCoT 视觉能力——尝试激活门控
================================================================================

  目标：让架构3的门控能够打开，使空间约束真正生效

  ── 路线1：Prompt 强化（今日第一阶段）───────────────────────────

  底层逻辑：
    VLM的注意力资源有限。不加引导时，模型倾向于给出泛泛的
    "temperate climate, deciduous trees"这种全球通用的描述。
    结构化清单Prompt强制模型关注中国地理的关键区分维度。

  实现：
    将三阶段Prompt从开放式"分析这张图"改成清单式：

    MACRO Prompt（~2500 chars）:
      □ 气候区 [ ]冰雪→高海拔/高纬度  [ ]茂密绿植→亚热带
              [ ]干燥稀疏→西北干旱区  [ ]棕榈→海南/版纳
      □ 地形   [ ]平原  [ ]丘陵  [ ]高山  [ ]喀斯特  [ ]沙漠
      □ 植被   [ ]针叶林  [ ]常绿阔叶林  [ ]混交林  [ ]草甸  [ ]竹子
      □ 城市   [ ]大城市  [ ]中等城镇  [ ]乡村  [ ]荒野

    REGIONAL Prompt（~3600 chars）:
      □ 文字   [ ]简体汉字  [ ]藏文  [ ]维吾尔文
      □ 建筑   [ ]白墙黛瓦马头墙→徽派/皖南
              [ ]碉房+经幡→藏区/川西
              [ ]土楼→闽西南
              [ ]骑楼→广州/闽南/广西
      □ 树种   [ ]法国梧桐→沪宁杭  [ ]榕树→华南
              [ ]香樟→长江以南  [ ]椰树→海南
      □ 山体   [ ]花岗岩(浑圆,灰蓝)→黄山/三清山
              [ ]石英砂岩(红棕,细柱)→张家界
              [ ]石灰岩(灰白,塔状)→桂林/阳朔
              [ ]丹霞(红层,水平)→武夷山/张掖

    LOCAL Prompt（~2100 chars）:
      区分相似地点：
      "花岗岩峰林 → 黄山(浑圆+松树) vs 三清山(尖锐+破碎) vs 华山(光秃+陡峭)"
      "喀斯特 → 桂林(塔状孤立+城市) vs 阳朔(密集塔状+乡村)"

  效果：
    旧Prompt: "Europe, temperate climate" → 完全错
    新Prompt: "四川盆地, 中国, 亚洲" → 国家对了，区域错了
    模型现在往正确的方向思考，但视觉分辨率没变

  ── 路线2：LoRA微调（今日第二阶段）───────────────────────────────

  底层逻辑：
    Prompt告诉模型"应该看什么"（注意力引导）
    LoRA微调让模型"学会怎么说"（输出风格调整）
    通过调整Qwen2-VL的attention投影层(q_proj/v_proj/k_proj/o_proj)，
    让模型学会KB风格的结构化地理描述

  训练数据生成：
    从7489张标注图按场景分层采样487张
    → 每张图根据GPS匹配最近的知识库条目
    → 自动生成训练回复："综合视觉分析，该图拍摄于XX省XX附近。
      地质特征：... 植被特征：... 文化标志：..."
    → 作为 (image, instruction, response) 三元组训练

  训练配置：
    模型: Qwen2-VL-2B (4-bit量化，减少显存占用)
    GPU: RTX 4060 Laptop 8.6GB
    LoRA: rank=8, alpha=16, target=[q_proj, v_proj, k_proj, o_proj]
    数据: 487条 (urban:125, karst_granite:125, alpine_snow:112, other:125)
    Epochs: 2, Batch: 1, GradAccum: 4
    时间: ~24分钟, Loss: 458→176 (-61%)

  效果：
    基座模型输出: "temperate climate, deciduous trees"（泛泛英文）
    LoRA模型输出: "红砂岩地貌、亚热带常绿林、峨眉山、贡嘎山、
                 成都平原红土壤、白墙古建筑"（结构化中文地名）

    LoRA教会了模型"说地理行话"——但它仍然看不清图片里到底是什么。
    视觉编码器没有本质提升，所以模型更自信地给出了错误答案。

  训练的局限性：
    数据是GPS邻近匹配而非图像内容匹配——一张离黄山0.4km的城市街景
    会被标注为"黄山花岗岩峰林"，这种不一致限制了训练效果

================================================================================
  架构演变的底层逻辑总结
================================================================================

  每次架构变化解决的核心矛盾：

  架构1→2: 解决"一个模型学不了全中国"
          方案：按场景分治，Router自动分配
          关键设计：场景类型是视觉可分的（城市≠雪山≠喀斯特）

  架构2→3: 解决"MoE没有地理常识"
          方案：GeoCoT为MoE提供空间先验
          关键设计：门控——GeoCoT看不清时关门，不添乱

  架构3→4: 解决"门控打不开"（未突破）
          方案：强化GeoCoT的视觉描述能力
          局限性：Prompt和LoRA改善的是"表达方式"，
                  改善不了VLM视觉编码器本身的"分辨率"

  核心矛盾：
    鳌太线级联的门控逻辑是正确的——Parser、SpatialKB、Constraint、
    Gate的代码都被调试过，工作正常。
    但它依赖GeoCoT能识别出具体的地理要素（特定岩石、树种、建筑风格）。
    Qwen2-VL-2B的视觉编码器做不到这个细粒度。
    代码在等一个更强的视觉模型。
