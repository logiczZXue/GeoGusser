# 学习计划 3：动手实践路线 — 改一行代码，学一个概念

## 理念

最好的学习方式不是看教程，而是**改代码 → 看效果 → 理解为什么**。
以下每个练习都是安全的（改坏了能改回来），但都能让你看到真实的效果。

---

## 练习1：观察模型输出的随机性 (10分钟)

**目标：** 理解 `temperature` 参数的作用

**步骤：**
1. 打开 `D:/Geocomp/src/Geocot/Geocot.py`
2. 找到第346行 `temperature: float = 0.7`
3. 改成 `temperature: float = 0.01`，运行同一张图3次
4. 再改成 `temperature: float = 1.5`，运行同一张图3次
5. 对比结果

**预期观察：**
- `0.01`：3次输出几乎一样（确定性高，缺乏多样性）
- `0.7`：3次输出有变化但方向一致（推荐值）
- `1.5`：3次输出差异大，可能跑偏（太随机）

**学到的概念：** temperature控制模型输出的"创造力"。低=保守，高=发散。

**改回来：** 改回 `0.7`

## 练习2：删掉LOCATION标记看效果 (10分钟)

**目标：** 理解结构化输出的重要性

**步骤：**
1. 打开 `D:/Geocomp/src/Geocot/prompts/local.txt`
2. 删掉最后两行（`IMPORTANT:` 和 `LOCATION:` 那几行）

**学到的概念：** 让模型输出结构化格式（如 `LOCATION: City, Country, Continent`）是AI工程的常用技巧，让代码能可靠地解析模型输出。

**改回来：** 把删掉的内容加回去

## 练习3：调整图像大小看效果 (10分钟)

**目标：** 理解图像分辨率对推理的影响

**步骤：**
1. 打开 `Geocot.py`，找到第288行 `MAX_IMAGE_PIXELS = 504 * 28 * 28`
2. 改成 `MAX_IMAGE_PIXELS = 100 * 28 * 28`（大幅缩小）
3. 运行一张图，观察推理质量

**预期观察：** 图像太模糊，模型可能无法识别细节（车牌、路标），推理质量下降。

**学到的概念：** 图像分辨率是精度和内存的权衡。太低丢细节，太高爆内存。

**改回来：** 改回 `504 * 28 * 28`

## 练习4：跳过某个阶段看效果 (20分钟)

**目标：** 理解3阶段推理链的作用

**步骤：**
1. 打开 `Geocot.py`，找到 `GeoCoTPipeline.run()` 方法（第314行）
2. 在 `for stage in GeoCoTStage:` 循环内，加一行跳过Stage 1：
   ```python
   if stage == GeoCoTStage.MACRO:
       result.stage_outputs[stage.value] = "(跳过)"
       continue
   ```
3. 运行一张图，看推理质量是否下降

**预期观察：** 没有宏观分析，区域分析可能方向跑偏（比如把热带误判为温带）。

**学到的概念：** 推理链的每个阶段都有用——宏观分析缩小范围，区域分析精确定位，局部分析给出最终答案。

**改回来：** 删掉跳过代码

## 练习5：修改提示词看效果 (15分钟)

**目标：** 理解提示词设计的影响

**步骤：**
1. 打开 `prompts/macro.txt`
2. 在气候分析后面加一行：`- Sky color and cloud patterns`
3. 运行一张图，看模型是否多讨论了天空和云
4. 再把 `macro.txt` 中的所有提示删掉，只留一行：`"Where is this?"`
5. 运行同一张图，对比推理质量

**预期观察：** 简单提示 → 模型给出模糊回答；详细提示 → 模型逐条分析。

**学到的概念：** 提示词是引导模型推理的"方向盘"。好的提示词不是问"这是什么"，而是告诉模型"从哪些角度分析"。

**改回来：** 恢复原始 `macro.txt`

## 练习6：观察GPU内存使用 (10分钟)

**目标：** 理解模型推理的内存开销

**步骤：**
1. 打开一个新终端，运行：`nvidia-smi -l 1`（每秒刷新GPU状态）
2. 在另一个终端运行推理
3. 观察推理过程中GPU显存的变化

**预期观察：**
- 加载模型时：显存从0跳到~4.5GB
- 处理图像时：显存短暂增加
- 生成文字时：显存随生成长度增长
- `torch.cuda.empty_cache()` 后：显存略微下降

**学到的概念：** GPU显存是有限资源。模型权重+图像数据+生成中间结果，全部要装进显存。

## 练习7：阅读模型的原始输出 (10分钟)

**目标：** 理解模型输出和代码解析的差距

**步骤：**
1. 在 `run_geocot.py` 第65行后加一行：
   ```python
   print(f"  [RAW LOCAL OUTPUT]\n  {repr(result.stage_outputs.get('local', ''))}")
   ```
2. 运行一张图
3. 仔细看模型输出的原始文本，注意它是否严格遵循了 `LOCATION:` 格式

**预期观察：** 模型有时候格式标准，有时候会多加内容（如"我推断这是..."），这就是为什么 `extract_prediction()` 需要多种模式匹配。

**学到的概念：** 大模型输出不可控，代码必须"防御性编程"——假设模型可能不按格式输出。

**改回来：** 删掉加的print行
